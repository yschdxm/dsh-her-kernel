通知与消息层

渠道消息只入库、记未读、按规则决定是否弹通知。消息本身不直接进入她的对话。
总览 心绪层 日子层 记忆层 通知与消息 会话与出站 规则触发 QQ 桥接

入站数据流

flowchart LR N[NapCat 事件] --> B[桥接 normalize] B --> I[kernel.ingest] I --> ROUTE{角色认领渠道?} ROUTE -->|否| SKIP[忽略] ROUTE -->|是| DB[(messages.db)] DB --> UN[未读计数] UN --> NT{是否可弹通知} NT -->|是| Q[进入通知列表] NT -->|否| ONLY[仅角标] Q --> EVAL[规则评估] EVAL -->|有可弹未读| INJ[kernel-wake 注入]

消息库

  • 每角色一个 messages.db。
  • 字段含渠道、目标、发送者、内容、时间、消息号、是否 @、已读状态。
  • 她的回复也会写入并标为已读，避免污染未读角标。

通知规则（按渠道配置）

规则工作逻辑
dmPriority私聊优先：到达即弹，不静默；并开启聚焦窗口。
atOnly群消息仅在 @她 时才进入可弹列表。
silentMinutes进入该 App 后的静默期；期间新消息只记未读。
format通知文案模板，支持 {source} {count} {target}。
notifyFocusMinutes私聊到达后，其它渠道通知被按住的分钟数。

未读如何变成她的回合

  1. 规则评估发现存在可弹未读。
  2. 通过通知闸门（开关、冷却、每日上限、夜间静默）。
  3. 注入 {"type":"kernel-wake","notifications":[...]}。
  4. 她用 App 工具查看；需要回时 app_send。
  5. 点开即消：工具 her_mark_read 或进入 App 翻页自动标已读。
有未读时心绪规则让路，避免「消息还没看又额外戳一次」。

设置位置

  • 渠道通知规则：角色面板 → 消息 → 渠道规则。
  • 通知注入开关与上限：设置 → 心绪闸门旁的「夜间静默与通知」。
  • 私聊聚焦屏蔽：同上 notifyFocusMinutes。
