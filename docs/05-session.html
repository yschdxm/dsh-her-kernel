会话与出站层

一个角色只活在一个专属会话里。注入与工具只挂这个会话；回复外发必须经过安全分类器。
总览 心绪层 日子层 记忆层 通知与消息 会话与出站 规则触发 QQ 桥接

单会话约束

  • 每个角色一个固定会话（按工作区路径创建/恢复）。
  • 人设、状态注入、工具经 agent.ctx 挂载，其它会话不可见。
  • 会话必须归属工作区（attachSession），否则界面会「跳出工作区」。
  • 会话不能停在归档态，否则每回合被平台拦成 blocked。

一回合的生命周期

flowchart TB TRIG[触发：主人消息 / kernel 注入 / 日程提醒] --> RUN[模型运行：读注入+工具] RUN --> STOP[回合结束 turn-stopping] STOP --> OUT{有渠道出站?} OUT -->|有| SEND[sendOutbound → 分类器 → 渠道] OUT -->|无| NOS[仅会话内可见，不外发] SEND --> OK[发送成功] SEND --> BLK[被拦截] BLK --> FLOW[回流 send-blocked 结构化通知] STOP --> EVAL[同时触发规则评估]

出站路径

  1. 她调用 app_send（需先 app_enter）。
  2. 内核 sendOutbound(channel, target, text)。
  3. 桥接分类器：关键词快筛 → 可选 LLM 审核 → 放行或拦截。
  4. 放行则发往 QQ；拦截则返回 reason。
  5. 自动回合被拦时，内核补一条 send-blocked 结构化通知，供她下一回合看到理由。
kernel 触发的回合若她没有调用出站工具，文本只留在会话里，不会自动发到 QQ。
