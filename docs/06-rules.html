规则触发层

事件驱动的评估器：决定「要不要给她开一回合、开哪种回合」。没有插件定时器。
总览 心绪层 日子层 记忆层 通知与消息 会话与出站 规则触发 QQ 桥接

主动意图（intent）

intent含义allowOutbound配额
seek_master来找主人说话/分享truedailyCap / cooldownMinutes
self_chore自己做事：写日记、看日程、翻群、整理记忆默认 falseselfDailyCap / selfCooldownMinutes 等
reflect只记 state_note / 写记忆，可不发消息false同 self

载荷 actions[] 只是数据提示（diary / schedule / memory_review / group_peek / quiet / share），具体怎么做由她按人设决定。夜间静默对规则路径仍生效。

何时评估

时机cause说明
渠道消息入库后ingest通知路径主入口
她任何回合结束turn-end含无出站的 kernel 回合；在「无出站早退」之前调用
桥接事件event被夸、被忽略、写记忆等

同一事件风暴用一次微任务合并，避免连环注入。这不是周期定时器。

评估流程

flowchart TB REQ[request cause] --> FL[合并后 flush] FL --> G0{角色启用? heart.enabled?} G0 -->|否| END[结束] G0 -->|是| DEC[decay + advance 算账] DEC --> UN{有可弹未读?} UN -->|有| NG[通知闸门] NG -->|过| W[kernel-wake] NG -->|不过| END2[规则也不跑，防堆叠] UN -->|无| SCAN[按序扫 rules] SCAN --> M{匹配 min/max/any/窗/忙闲/静默?} M -->|否| NEXT[下一条] M -->|是| GG[全局闸门] GG -->|不过| NEXT GG -->|过| CH[概率 chance] CH -->|不过| NEXT CH -->|过| H[kernel-heart 纯 JSON] H --> RI[recordInject 节流] NEXT --> DONE[一次最多一条]

{
  "id": "miss-pm",
  "name": "午后想念",
  "enabled": true,
  "when": {
    "min": { "miss": 70 },          // 各维 ≥（含抖动）
    "max": { },                     // 各维 ≤

    "silenceMin": 45,               // 主人静默分钟
    "sinceSpokeMin": 60,            // 距上次开口分钟
    "windows": [ { "from": "13:00", "to": "19:30" } ],
    "weekdays": [],                 // 空 = 每天
    "activityIn": [],               // 非空则活动必须在列表内
    "activityOut": [ "sleep", "night", "out" ],
    "maxUnread": 0

  "jitter": {
    "thresholdPct": 12,             // 阈值 ±12%

  "cooldownMinutes": 120,
  "materials": { "timeline": 6, "diary": true }
}

全局闸门（配置在 heart.gates）

闸门逻辑
夜间静默落在 quietHours 区间则不注入
每日上限当日 rule 注入次数 ≥ dailyCap 则停
规则冷却距上次 kernel-heart 不足 cooldownMinutes 则停
静默 / 距开口低于 minSilence / minSinceSpoke 则停
未回复不叠加已发出且主人未回、仍在宽限期内则停

为什么没有定时器

  • 周期唤醒会让回合看起来像「有人叫她」，与「自己的状态变化」混淆。
  • 完全无事件的深夜不评估——这是有意取舍。
  • 需要定时自查时，角色使用平台日程工具创建提醒，属于她设定的任务。
  • 作息换段靠惰性推进：下次任何事件评估时才会看到新活动。
